# ytmGO 滚动封面缓存方案

首页卡片在 Retina 屏上通常需要 384 px 的封面。旧实现长期保存 RGBA 像素，每张正方形卡片含缩小层级约占 768 KiB，32 MiB 共用池约能容纳 42 张。浏览较长的首页再返回时，播放器大图和首页卡片会相互挤占，部分带合法参数的 Mix 封面还会再次下载。

## 显示与回收

按控件的逻辑尺寸乘以窗口所在显示器的倍率，在 128、384、768 px 中选择足够的档位。移动窗口、调整窗口大小和修改显示配置都会更新倍率。支持指定尺寸的 CDN 直接返回目标版本。其他图片在后台按比例缩小，透明图使用 PNG，完全不透明的缩放图使用 JPEG。每次下载上限为 4 MiB，源图每边最多 4096 px，总面积最多 4,194,304 像素，同时最多解码两张。

在软件渲染并发回归中，MyGo 0.7.1 的多个绘制线程会同时恢复同一张图的像素。项目升级到 0.7.2，该版本在软件渲染分派任务前统一恢复像素。

MyGo 的 `DecodeBitmap` 保留可恢复像素的压缩数据。界面把位图交给渲染器后安排下一帧，在主线程调用 `ReleasePixels`。已有纹理可以继续显示，纹理被驱逐时从同一个位图恢复。取色在加载时完成。命中其他分辨率时可以立即显示，大图交给 MyGo 的缩小层级绘制，小图则先显示并排队补高清。窗口第一次布局时也可以查找新鲜的已有封面。

| 缓存用途 | 字节上限 | 条目上限 |
| --- | ---: | ---: |
| 128 px 缩略图 | 16 MiB | 512 |
| 浏览卡片、合集封面 | 48 MiB | 512 |
| 大于 128 px 的播放器封面和下一首预载 | 16 MiB | 32 |

浏览池额度最大。60 张 384 px 正方形卡片在释放像素前的像素和缩小层级合计约 45 MiB，热缓存只需保留各自的压缩数据。播放器的常用工作集是当前曲目、下一首和切换期间的上一张封面，一张 768 px 正方形封面的像素和缩小层级约占 3 MiB。缩略图池另设 512 项上限，限制长列表里大量小文件对应的对象数量。

首次请求确定归属。同一 URL 和尺寸共享下载任务、位图和一份额度。每池对压缩数据及尚待释放的像素和缩小层级计账，三池总计最多 80 MiB。当前视口、本帧使用的备用尺寸和下一首预载优先保留，空间不足时按最近使用顺序淘汰闲置条目。解码工作区、HTTP 缓冲、GPU 纹理和应用其他部分单独占用内存。上限之外的旧图可能需要从磁盘异步恢复。

## 网络与磁盘

公开封面使用 `httpcache` 处理 HTTP 新鲜度、`Vary` 和条件验证。新鲜条目直接复用，过期时依据 `ETag` 或 `Last-Modified` 询问服务器，收到 304 后复用已有正文。显示着的图片可以持续绘制，再次进入视口时检查可复用期限。同一 CDN 地址同时需要不同像素尺寸时，后到的任务等待第一次 HTTP 操作完成。账号头像绕过磁盘缓存。带查询参数的图片只对曲库已识别的公开 Mix 接口开放磁盘缓存。

每个 HTTP 表示把索引行和正文写进同一个临时文件，再原子替换。操作系统文件锁协调多个应用实例的读取、写入和淘汰。目录沿用已发布版本的专用封面目录，首次写入清理旧格式和崩溃遗留的临时文件。升级后旧格式的封面会按需取回一次。

磁盘上限为 512 MiB，所有 URL 和同一 URL 的多个表示都按占用字节计费。写前按文件系统分配单位预留临时文件空间，替换期间把新旧两份都计入额度。预计超额时按 URL 的最近使用时间淘汰整组封面，直到含本次写入在内的占用降至额度的 80%（约 409.6 MiB）。卷上剩余空间不足 256 MiB 加本次写入量时，先回收其他闲置封面，再检查实际可用空间。仍不足或无法可靠查询时，本次图片继续显示并跳过持久化。

## 验收

用确定性图片和可计数的 HTTP 上游驱动原生首页、240 项列表、播放器、窗口缩放和页面返回，分别记录高清位图复用、回看新下载的正文、占位图、帧时间和内存。另用故障注入覆盖取消、304、缓存策略改变、损坏数据、磁盘容量、卷余量及多进程竞争。复现方式和实测边界见[验收记录](acceptance.md)。
