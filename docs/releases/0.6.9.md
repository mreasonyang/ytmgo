# ytmGO 0.6.9

Windows and Linux now expose **Help → Check for Updates…**. Previous releases placed the only manual update action in the macOS application menu, which MyGo hides on these platforms. The entry opens the existing native updater, using the same signed update feed and installation flow. macOS keeps **ytmGO → Check for Updates…**.

Custom global playback shortcuts now preserve existing platform menu shortcuts: **F11** on Windows/Linux, **Ctrl+Y** on Windows, and **Control+Command+F**, **Option+Command+H** and **Option+Shift+Command+V** on macOS. Conflicting keys are rejected while recording; previously saved conflicts fall back to the default global playback shortcut at startup.

Regression checks verify that each platform has exactly one reachable update entry, important menu actions remain reachable after menu rebuilds, and global playback bindings cannot take over visible menu accelerators. Playback-recovery policy tests now use controlled heard-progress samples, avoiding a dependency on hosted audio-device timing while preserving the production recovery threshold and native audio checks.

Existing Windows/Linux installations with the hidden entry can use `--check-for-updates` and `--install-update`, or install the new package. Linux DEB installations under system-owned `/opt/ytmgo` should be upgraded with `apt`.

macOS 13 or newer, Apple Silicon and Intel. macOS packages are Developer ID signed, notarized and stapled; all four release targets use Ed25519-signed update archives. Windows installers are not Authenticode signed. Menu-model and native UI regressions are separate from real-account playback and physical-key acceptance on each platform.

0.6.8 was not published: its Intel source-test job exposed the device-dependent recovery test. This release includes the corrected test and policy sampling boundary.
